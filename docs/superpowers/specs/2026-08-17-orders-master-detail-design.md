# 주문 목록·상세 테이블 설계

## 목표

기존 주문 mock API를 사용해 한 화면에서 주문 목록을 검색·페이지 이동하고, 선택한 주문의 상품 상세를 확인한다.

## 범위

- 주문번호 또는 고객명 키워드 검색
- 주문 상태 검색
- 한 페이지에 주문 5건 표시
- 이전·페이지 번호·다음 페이지네이션
- 상단 주문 목록과 하단 상품 상세의 2단 배치
- 최초 조회, 검색, 페이지 이동 후 첫 번째 주문 자동 선택
- 사용자가 목록 행을 클릭하면 해당 주문으로 선택 변경
- 목록과 상세의 로딩·오류·빈 결과 안내

히스토리 탭, 정렬, 주문 수정, URL 검색 조건 동기화, 외부 서버 연동은 이번 범위에서 제외한다.

## 구조

- `OrdersPage`: 검색 조건, 페이지, 선택된 주문, 목록·상세 요청 상태를 관리한다.
- `OrderListTable`: 주문 요약 목록과 선택 상태를 표시하고 행 선택 이벤트를 전달한다.
- `OrderDetailTable`: 선택된 주문의 상품 행을 표시한다.
- 기존 `getOrders`와 `getOrderDetail`을 그대로 사용하고 새 데이터 라이브러리는 추가하지 않는다.
- 기존 shadcn `Table`, `Pagination`, `Input`, `Select`, `Button`, `Badge`, `Spinner`를 조합한다.

## 데이터 흐름

1. 화면 진입 시 `getOrders({ page: 1, pageSize: 5 })`를 호출한다.
2. 목록 응답의 첫 행을 선택하고 해당 `orderId`로 상세 API를 호출한다.
3. 검색 버튼을 누르면 입력된 키워드·상태를 적용하고 페이지를 1로 초기화한다.
4. 페이지를 이동하면 같은 검색 조건으로 목록을 다시 불러온다.
5. 검색 또는 페이지 응답마다 첫 행을 새로 선택한다.
6. 행을 직접 선택하면 목록 요청 없이 상세만 다시 불러온다.
7. 목록이 비어 있으면 선택과 상세를 모두 비운다.

## 표시 항목

주문 목록은 주문번호, 주문일시, 고객명, 상태, 상품 종류 수, 총 수량, 총 금액을 표시한다. 상세는 상품코드, 상품명, 옵션, 수량, 단가, 합계를 표시한다. 금액은 한국 원화 형식, 일시는 한국어 날짜·시간 형식으로 표현한다.

## 오류 처리

목록 요청이 실패하면 목록 영역에 오류와 `다시 시도` 버튼을 표시한다. 상세 요청 실패는 하단 영역에서만 처리해 목록 탐색을 유지한다. 빠르게 선택을 바꿀 때 늦게 도착한 이전 요청이 최신 선택을 덮지 않도록 effect 정리 시 응답을 무시한다.

## 테스트

- 최초 목록의 첫 주문이 자동 선택되고 상세가 표시되는지 확인한다.
- 검색 후 결과의 첫 주문으로 선택이 갱신되는지 확인한다.
- 다음 페이지 이동 후 해당 페이지 첫 주문이 선택되는지 확인한다.
- 다른 행 클릭 시 하단 상세가 바뀌는지 확인한다.
- 빈 목록과 목록 오류 상태를 확인한다.
